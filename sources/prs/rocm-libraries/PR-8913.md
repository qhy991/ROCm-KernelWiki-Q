## Description

> Fixes #8878. Reusing `hipsparseSpGEMM_compute()` to recompute `C = A*B` after updating the values of A (or B) in place leaves C unchanged. This prevents the common pattern of computing an SpGEMM once (fixed sparsity structure) and re-running only the numeric phase when input values change.
