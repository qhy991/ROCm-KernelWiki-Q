# gfx942 FP16 D128 Prefill With a Depth-2 Sliced-K Ring

## Summary

This PR restores the rocKE sliced-K ring path for FP16 attention with head
dimension 128 on gfx942. A previous depth-3 schedule used `kg % 3` for four K
groups, so the fourth slice reused LDS slot 0 while an unfenced DMA could
overwrite data still needed by MFMA. An intervening correctness fix routed D128
to a slower non-ring implementation.

The replacement has two parts:

1. An unconditional drain of LDS reads plus a barrier before a prefetch DMA
   reuses the slot read by the preceding slice.
2. A per-spec `ring_depth` setting. FP16 D128 uses two slots (`kg % 2`), while
   D64 retains the existing depth-3 schedule and BF16 D128 stays non-ring.

Depth 2 reduces the live LDS set and the associated occupancy pressure while
avoiding the unsafe slot lifetime.

## Source-Reported Performance

The PR compares the new path with the non-ring correctness fallback and
AOTriton FlashAttention on MI300X using FP16 D128 inputs.

| Shape | Non-ring vs AOTriton | Depth-2 ring vs AOTriton | Ring speedup |
|---|---:|---:|---:|
| Hq/Hkv 32/8, S1024 | 0.68x | 0.88x | 1.29x |
| Hq/Hkv 32/8, S4096 | 0.92x | 1.42x | 1.54x |
| Hq/Hkv 128/8, S1024 | 0.70x | 1.06x | 1.51x |
| Hq/Hkv 128/8, S4096 | 0.99x | 1.55x | 1.56x |
| Hq/Hkv 16/16, S4096 | 0.80x | 1.17x | 1.46x |

These are upstream PR measurements, not local reproductions in this Wiki.

## Correctness Evidence

- FP16 D128 passed against an FP32 oracle at magnitude inputs, with reported
  maximum absolute error around `0.002`.
- BF16 D128 remained on the non-ring path.
- FP16/BF16 D64 retained the depth-3 path.
- The PR reports 177 attention tests passing.

## Scope and Limits

The ring schedule is authored in rocKE's Python engine. The PR explicitly
notes that the attention path is not covered by the byte-identity gate against
a C++ mirror. Treat the performance and numerical results as source-reported
until the exact merge commit is reproduced on gfx942.
