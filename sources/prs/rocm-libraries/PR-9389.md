# fix(tensilelite): defer non-E8 MX scales to slow reference path

Merged PR #9389 in [ROCm/rocm-libraries](https://github.com/ROCm/rocm-libraries/pull/9389).

**Author:** geotseng-amd
**Merged:** 2026-07-14

## Description

> The fast MXFP4 CPU reference (added in #8106) reinterprets the MX scale tensors as E8 (UE8M0) unconditionally, ignoring DataTypeMXSA/MXSB. For F8 (E4M3) or E5M3 scale blocks this mis-decodes the scale (exponent instead of float) and yields a wrong validation oracle, so gfx1250 MXFP4 tests fail for f8/e5m3 scales while E8 passes.
