# gfx950 Persistent Dense FlashAttention Prefill

## Summary

This PR adds a rocKE dense causal prefill implementation for gfx950. It
combines a persistent grid-stride schedule with several lower-level changes:

- a transposed PV layout aligned with the CK-1 formulation;
- K-tile LDS padding;
- native `exp2_fast` in the online softmax path;
- partial-`vmcnt` prefetch overlap;
- a PV-only priority adjustment;
- vectorized output stores.

The persistent launch keeps a bounded grid resident and assigns subsequent
attention tiles through grid-stride iteration. That is distinct from claiming
that persistence alone explains the result: the PR lands it together with the
LDS, softmax, prefetch, MFMA, and store changes above.

## Source-Reported Performance

On MI355X/gfx950 with BF16, head dimension 128, `Hq=128`, `Hkv=8`, causal
attention, and sequence length 8192, the PR reports roughly `940-970 TFLOPS`
for the persistent path with `num_persistent=256`, versus about `543 TFLOPS`
for the default path. It also reports:

- maximum absolute error around `1.46e-3`;
- 250 VGPRs;
- zero reported spills.

The source page preserves these as a combined-kernel result. It does not
attribute the full gain to any one optimization.

## Scope and Limits

The implementation is gfx950-specific and cannot be performance-validated on
a gfx942 node. The merged change includes the C++ `exp2_fast` mirror and
Python/C++ lowering coverage, but the PR notes that its golden test was not
yet wired into CI. The performance result remains source-reported.
