# gfx950 D128 Softmax-MFMA Interleave and Four-Wave Dispatch

## Summary

This PR changes the single-batch D128 gfx950 prefill schedule in two coupled
ways:

1. It interleaves online-softmax work with MFMA instead of serializing the two
   phases.
2. It changes the selected launch from two to four waves.

The reported resource change is substantial: VGPR usage falls from 296 to 250,
AGPR usage falls from 40 to 0, resident waves per CU increase from four to
eight, and reported occupancy rises from 11.8% to 23.5%.

## Source-Reported Performance

For Llama-3.1-405B D128 BF16 prefill at batch 1, causal sequence length 8192
on MI355X/gfx950, the PR reports:

| Metric | Before | After |
|---|---:|---:|
| Throughput | 333.9 TFLOPS | 440.7 TFLOPS |
| Occupancy | 11.8% | 23.5% |
| Waves per CU | 4 | 8 |
| VGPR | 296 | 250 |
| AGPR | 40 | 0 |

Across the source's S512-S8192 test sweep, the largest reported speedup is
`3.6x`. The exact gain is shape-dependent and should not be generalized to
other head dimensions or architectures.

## Correctness Evidence

The PR reports that selector output is unchanged outside the targeted cohort.
For the enabled path it reports `max_abs=0.0` against the previously shipped
kernel and approximately `8.2e-3` against an independent PyTorch dense causal
reference. The PR checklist left the separate byte-identity command unchecked,
so this page does not claim that gate was run.

## Scope and Limits

The selector is architecture- and shape-specific. The result supports the
general lesson that scheduling and launch geometry must be tuned together, but
the numerical TFLOPS values are source-reported gfx950 measurements.
